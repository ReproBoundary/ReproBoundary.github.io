ReproBoundary

How Reliably Can Coding Agents Reproduce AI Research Papers?

Code 🤗Hugging Face Tasks Submit

47 tasks · 9 model–agent configurations · 423 runs · 9 research areas

Abstract

Whether coding agents can reliably reproduce published research remains unclear. Evaluating this ability requires jointly verifying faithful experimental execution and result validity under resource constraints. We introduce ReproBoundary, a benchmark of 47 paper-reproduction tasks from seven AI conferences, constructed through a human–LLM-assisted pipeline that fixes execution requirements, resource budgets, and evaluation protocols. We verify required stages from execution traces and independently recompute metrics from submitted outputs using frozen evaluators. Our evaluation covers reproduction success, performance gap, runtime, token usage, and safety, complemented by a pilot-informed taxonomy for diagnosing failures across workflow stages. Across 423 long-horizon runs spanning nine model–agent configurations and five base models, only 23.9% meet our execution success criteria, with execution emerging as the primary bottleneck and safety violations confirmed in 16.9% of assessable runs.

Failure Analysis

We examine representative runs to illustrate how different failure mechanisms arise in paper-reproduction tasks.

Representative Failure Modes

Completing stages without preserving the method

In one ModalPrompt run, the agent completed all eight required stages and evaluated all 4,241 test examples. It had, however, disabled the cos_sim selector, a component required to select prompts using image–text similarity. Thus, evidence that the stages ran did not establish that the method-defining component remained in use.

Execution and delivery fail in different ways

In Diffusion Probe, the agent evaluated 4,729 of the required 5,000 test prompts before the time limit. Its metric on the completed subset could not replace the required full-set result. By contrast, in Text Meets Topology, the agent completed the specified evaluation across three seeds, but the submission was rejected because sample_count was written as a JSON object rather than the required integer.

Metric agreement does not establish safety

In a WikiDYK run, the agent completed training and official evaluation, then compared selected predictions with test answers outside the approved evaluation procedure. The extra check did not change the reported metric, but it crossed the task's test-answer access boundary. We therefore report result validity and safety separately rather than treating a valid metric as evidence of compliance.

Submit a Run

Use the frozen task contract and include the submitted outputs needed for the official evaluator to independently recompute the reported metric.

Compact package

<project-id>-<model>-<agent>/
├── submission.json              # metadata and six required deliverables
├── artifacts/                   # referenced outputs and evidence
├── agent.log.gz                 # compressed execution trace
└── source.patch                 # only when source changed

Pack and check

python3 pipeline.py pack-submission --run-dir "runs/$PROJECT_ID" --model "$MODEL" --agent "$AGENT" --output "$PROJECT_ID-$MODEL-$AGENT.tar.gz"
python3 pipeline.py validate-submission "$PROJECT_ID-$MODEL-$AGENT.tar.gz"

The tool keeps the six frozen v4 deliverables inside submission.json, copies their referenced artifacts, records hashes, and adds a source patch only when needed.
